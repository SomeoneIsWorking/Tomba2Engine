## What it is

Two-byte SJIS/token string emitter used by `Font::glyphEmit`'s control bytes 0x01..0x04 and the
options/menu builders. It decodes direct fullwidth letter/digit ranges or the token table at
0x800A55E0, emits fixed 8x8 op-0x75 sprites, handles newline/advance-only tokens and optional
combining marks, then appends the draw-mode packet.

## Native producer

`Font::iconGlyphEmit` owns both halves from one authoritative token walk: byte-exact guest
scratchpad/packet-pool/OT writes for the retained execution seam, and read-only RQ_HUD quads for
pc_render. The prior `iconGlyphTap` ran the authenticated executable/overlay evidence and decoded the same string again; that
duplicate substrate dependency is removed. The authenticated executable/overlay evidence remains only as the oracle leg.

## Evidence

Ghidra and the generated ABI agree on a 64-byte frame with nine spills, the two-byte token decoder,
packet cursor 0x800BF544, OT base pointer 0x800ED8C8, and calls to 0x8009A640/0x80083DE0. The focused
selftest runs 98 cases including every direct class, table miss, newline, all 90 actual MAIN.EXE token
entries and both synthetic combining-mark variants; every byte of RAM/scratchpad plus registers and hi/lo
matches the real MIPS interpreter.
The host negative control proves the queue reports one direct glyph, both two-glyph combining variants
with distinct U=56/64 marks, and no glyph for an unmapped token.
