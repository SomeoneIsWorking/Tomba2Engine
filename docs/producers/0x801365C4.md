## What it is

A TILED VERTICAL QUAD STRIP — the rope / cable / chain class. `a0` = node, `a1` = the strip's LENGTH.
The emitter divides the length by 120, emits that many full quads stepping Y down by 120 each time,
then one final quad covering the remainder, so the strip runs from `y = length` at the top down to
`y = 0` in fixed 120-unit tiles. Every tile carries the SAME four UVs, which is what makes it a
repeating rope texture rather than one stretched sheet.

Each tile in model space is the flat quad `(0, yTop, -half) (0, yTop, +half) (0, yBot, -half)
(0, yBot, +half)` — X is written as literal zero for all four corners, and the width is `node+0x6C`
halved toward zero, applied on Z. Material: GP0 code 0x2D (textured quad, RAW, not semi-transparent),
tpage `node+0x60`, clut `node+0x62`, UVs `node+0x64/0x66/0x68/0x6A`.

WHERE IT SHOWS: kanban #103 — the cutscene machinery's cable, and very likely the USER's missing
bridge ropes. Observed on node 0x800FE408, whose behaviour handler is `beh_event_record_machine`.

## Native producer

`game/render/fx_rope_strip.cpp` — `Render::ropeStripRender`, installed over 0x801365C4 (the override
runs the real `ov_a00_gen_801365C4` body first, so the guest emission and therefore psx_render / the
oracle / SBS are unchanged, then adds the native picture inside pc_render's native field-pass window
only).

WHY A PRODUCER WAS POSSIBLE AT ALL. This emitter reaches the picture only through FUN_8003B320
(`game/render/quad_rtpt_submit.cpp`), a faithful substrate mirror that fills the guest packet and
OT-links it and pushes NOT ONE native primitive — its own banner says so. Eleven guest functions call
FUN_8003B320 and each composes its own CR0-7 contract before doing so, so there is no single transform
to project by at that leaf, and reading the transform back out of the GTE control registers is banned
outright (USER 2026-08-04). The contract had to come from the CALLER, and FUN_801365C4 has exactly one:

    FUN_80136748:  rec = mem32(node+200)
                   WORLD_POS = (mem16(rec+44), mem16(rec+48), mem16(rec+52) + 46)
                   FUN_80084470(CAM_ROT, WORLD_POS, mat)   -> mat.t = CamRot * WORLD_POS
                   mat.t += CAM_TRANS
                   FUN_80084660(CAM_ROT)  -> CR0-4 = the PURE CAMERA rotation (no object rotation)
                   FUN_80084690(mat)      -> CR5-7 = that composed translation

so a model corner M projects as `CamRot*(M + P) + CamTrans` — THE CORNERS ARE WORLD SPACE, offset from
the object's own world position P. The producer re-derives P from the node's own record and projects
with the native scene camera. No GTE readback, no packet inspection, no factored guest matrix.

SCOPE, stated honestly: this covers the FUN_80136748 caller class and no other. The other ten callers
of FUN_8003B320 each need their own transform RE'd — see kanban #103 for the shape that would
generalise it (submitQuad pushes natively when the caller has DECLARED a projection, and counts the
calls that arrive undeclared instead of dropping them silently).
