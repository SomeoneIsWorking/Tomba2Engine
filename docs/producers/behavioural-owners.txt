# behavioural-owners.txt — guest writers whose behaviour IS natively owned but whose owner records no
# guest address, so tools/codemap.py cannot see it (its own declared blind spot #3: "a native that
# reimplements this guest fn but records the address NOWHERE").
#
# CONSUMED BY tools/producer_frontier.py, which merges these into the frontier it emits for
# external/psxport/tools/producer_class.py --frontier. Without them that pipeline reports these
# addresses as outstanding shared dependencies, which is how the R1 effect-mesh row successively
# carried "4", "1" and "2" outstanding deps when the real answer was 0
# (docs/unported-render-inventory.md, R1 WORK ORDER).
#
# THE BAR FOR ADDING A ROW, because this file can silently retire a judgement call nobody made — the
# most dangerous direction of error in the whole producer pipeline:
#   1. name the native owner as file:line, and
#   2. cite the in-tree evidence that it owns THIS guest writer's behaviour (a source comment stating
#      the equivalence, or a docs/re/ analysis), and
#   3. state what the native does with the guest fn's DEPTH CUE — an owner that silently drops the cue
#      is not an owner, it is a producer with a missing parameter.
# A row that cannot state all three does not belong here. Prefer fixing the address tag at the
# definition so codemap indexes it, and delete the row when you do.
